# Project Insights & Architecture (by Gemini)

This project was initialized and refined using **Antigravity by Gemini**. Below are specific architectural decisions and technical highlights incorporated during the generation process.

## 🧠 Architectural Highlights

### 1. Unified Reverse Proxy (Nginx)
Instead of exposing multiple ports to the host machine, Gemini configured a central Nginx edge router. This allows the Frontend (React) and Backend (API) to coexist on the same origin (Port 80), simplifying CORS handling and providing a production-like networking environment.

### 2. Intelligent Service Orchestration
The `docker-compose.yml` implements a sophisticated `healthcheck` pattern:
- **Database Readiness**: Uses `pg_isready` to ensure the Postgres engine is fully initialized.
- **Dependency Condition**: The backend uses `condition: service_healthy` rather than just `depends_on`, preventing intermittent connection failures during the initial stack startup.

### 3. Data Integrity & Entities
- **TypeORM EntitySchema**: Used standard JavaScript schemas to define a One-to-Many relationship between `Patient` and `Order`.
- **Auto-Sync**: `synchronize: true` is enabled in the backend to ensure the database schema stays in sync with code definitions during development.
- **Automatic Seeding**: Logic inside `index.js` detects an empty database and automatically inserts a default "John Doe" record to ensure a functional UI out of the box.

### 4. Multi-Stage Frontend Build
The React build process is split into stages:
1. **Builder**: Uses Node.js to compile and build the production bundle.
2. **Server**: Discards the heavy Node environment and serves only the static assets via a lightweight Nginx-alpine image, optimizing the final image size.

## 🚀 Recommended Next Steps

- **Environment Variables**: Move hardcoded DB credentials in `docker-compose.yml` to a `.env` file for enhanced security.
- **Volumes**: Ensure persistent storage is backed up or mapped to a specific host folder if migrating to production.
- **Backend Refactoring**: Split the `index.js` into Controllers, Services, and Routes as the application grows.
